# Dola Studio 新人指南：两种模式，从 10 秒到 15 秒

适用版本：**1.0.1**。 [返回项目首页](../README.md)

**Dola Studio 是一款面向豆包与 Dola 的批量管理工具**，提供账号、代理、任务和作品的集中管理。针对 Dola 默认 10 秒的视频生成限制，提供聊天模式、工作模式两种方案，扩展至 **15 秒，支持 720P 输出**，并通过统一 API 连接其他网站与应用。本指南重点讲两种模式的实际使用方式。

两种方案都会向上游实际提交视频生成请求。已有验收中，两种模式分别生成了可播放的 15 秒、1280×720 横屏作品；具体账号是否能用，要以当前登录态、权限、额度和回执为准。

## 先看这一张表

| 项目 | 聊天模式 | 工作模式 |
| --- | --- | --- |
| 在哪里生成 | Dola 聊天会话 | Dola 工作空间 / 协作入口 |
| 模型 | Seedance 2.0 Fast | Seedance 2.0 Fast |
| 视频时长 | 15 秒 | 15 秒 |
| 输出目标 | 720P；已有横屏样例为 1280×720 | 同左 |
| 首次视频条数 | 1 条 | 1 条 |
| 主要条件 | 有效登录、可用账号代理、浏览器环境、模型可用额度 | 还需要可进入工作空间，且工作额度可用 |
| 参考图片 | 支持对应聊天 15 秒流程 | 支持对应工作流程 |
| 参考音频 | 仅 Dola Fast + 聊天模式 + 15 秒 | 当前不支持 |
| API 的模式字段 | `"execution_mode": "chat"` | `"execution_mode": "work"` |
| 首次如何选择 | 可以先用此模式跑通单条，再验证工作模式 | 已有可用工作账号时，可以直接选用 |

这两种模式是不同的提交与执行路径。聊天模式也会使用浏览器；不能把它理解为完全不占浏览器资源的轻量接口。哪一种更快、更稳定，需要在相同账号条件和网络下实测。

## 一、开始前准备什么

### 网站已经部署好

准备好以下内容即可开始：

1. 可访问的 Dola Studio 网站，以及管理登录账号。
2. 至少一个可正常登录的 **Dola 账号**。
3. 已在代理管理中添加、启用并可从服务器访问的代理。
4. 账号当前没有登录、验证或生成任务占用。
5. 服务器已经具备相应浏览器、依赖和显示环境。

先登录控制台，依次看“代理管理”和“账号管理”。把选定代理绑定到准备生成的账号，再点击该账号的“验证”，确认登录状态。

在账号行“更多 → 设置代理”中可以更改绑定。首次使用两种 15 秒方案时，建议明确绑定一个启用的账号代理，便于定位失败原因。只在浏览器所在的个人电脑上配置代理，不代表服务器已经能通过这个代理访问 Dola。

账号导入成功只说明数据已保存；“验证”通过说明当前登录检查通过，仍需一次实际生成确认 15 秒能力。勾选跳过在线验证的 Cookie 账号尤其需要补做这一步。

### 尚未部署网站

先完成 [README 快速开始](../README.md#quick-start)。当前推荐 Linux、Python 3.11+、单进程 Uvicorn，并准备 Node.js、FFmpeg / ffprobe、CloakBrowser 及浏览器系统依赖。有头浏览器还需要 DISPLAY 或 Xvfb。

Cookie 账号使用浏览器运行环境时，配置示例为：

```dotenv
DOLA_COOKIE_RUNTIME=cloak
DOLA_CLOAK_HEADLESS=0
DOLA_MAX_CONCURRENCY=1
DOLA_WORK_15S_CONCURRENCY=1
DOLA_LOGIN_CONCURRENCY=1
```

这些配置写入实际使用的环境配置文件，由部署者在空闲维护时加载。已有网站可能还有面板保存值覆盖环境默认值。它们不代替浏览器安装、代理绑定或账号登录。

`DOLA_COOKIE_RUNTIME=cloak` 用于 Cookie 账号的浏览器执行条件；只修改这个值，不会自动登录账号或开通工作权限。普通纯 HTTP Cookie 账号不能直接承担 Dola 工作模式。当前完整 Docker 部署尚未完成验收，首次验证这两种模式建议采用已准备好的 Linux 浏览器环境。

## 二、先把账号和模型选对

本指南的“10 秒到 15 秒”操作，针对 **Dola 账号 + Seedance 2.0 Fast**。

在“账号管理”添加账号时，按实际账号选择现有登录或 Cookie 导入方式；随后绑定代理并验证。不要把豆包账号当作 Dola 账号使用，两者对应的模型与执行路径不同。

| 要做的事 | 账号 | 模型与模式 |
| --- | --- | --- |
| 验证 Dola 聊天 15 秒 | Dola | Seedance 2.0 Fast + 聊天模式 |
| 验证 Dola 工作 15 秒 | 有工作入口及额度的 Dola | Seedance 2.0 Fast + 工作模式 |
| 批量管理豆包账号并生成 | 豆包 | 使用 `doubao-` 开头的对应模型，模式受账号类型约束 |

当前界面不支持给 Dola Seedance 2.5 选择工作模式。因此首次照本指南操作时，请保持 **Seedance 2.0 Fast**，避免把其它模型的能力和这两种方案混在一起。

## 三、方案一：聊天模式生成 15 秒

### 第 1 步：打开生成配置

1. 打开左侧“创作工作台”。
2. 在生成账号下拉框中选择一个已验证、当前闲置的 Dola 账号。
3. 点击“聊天模式”卡片，填写画面描述，打开生成配置窗口。

也可以从“账号管理”中找到该账号，点击行内的 **“生成”** 按钮，直接打开配置窗口。

### 第 2 步：逐项确认参数

| 配置项 | 首次填写 |
| --- | --- |
| 模式 | 聊天模式 |
| 视频模型 | Seedance 2.0 Fast |
| 视频时长 | **15 秒** |
| 画面比例 | 16:9，之后可按需要调整 |
| 视频条数 | **1 条视频** |
| 参考素材 | 首次留空，只用文字 |

可以使用下面这段提示词，也可以保留窗口内置的默认提示词：

> 清晨，平静的湖面映着远山和淡金色天空，微风轻轻吹动岸边芦苇，薄雾缓缓飘散，画面中没有人物、文字、标志或音乐，固定机位，连续自然镜头，写实自然风景，柔和光线，时长15秒。

**时长下拉框必须选择 15 秒。** 只在提示词写“15 秒”，但参数仍为 10 秒，不等于使用了本项目的 15 秒方案。

### 第 3 步：提交并观察

1. 点击一次 **“开始生成”**。
2. 如果出现账号状态或额度提醒，先看清原因；修复缺少代理、登录失效等问题后再提交。
3. 收到任务 ID 后，进入“任务列表”查看同一条任务。
4. 等待准备、提交、生成和结果处理完成，再到“视频作品”预览。

前端发送的模式是 `chat`。后端遇到 **Dola Fast + 15 秒** 组合时，会自动规范化到专用 `force15` 流程。看到日志或任务中出现 `force15` 是正常的，它对应界面的聊天 15 秒方案，不需要再找一个额外模式按钮。

这个流程不是单纯把提示词改成“生成15秒”：程序会准备聊天会话、处理参数与素材，确认提交并跟踪同一会话的结果。上游如果没有接受生成或明确拒绝，任务仍会失败。

### 第 4 步：首次成功后再添加素材

打开生成配置中的“添加参考素材”，逐次增加素材：

- 图片：JPG、PNG、WebP，最多 30 张，单张不超过 20 MiB。
- 音频：MP3、WAV、M4A、FLAC、OGG，最多 3 个，单个不超过 20 MiB、时长不超过 90 秒。
- 表单中图片与音频合计不超过 60 MiB，仍受后端各阶段检查。

音频只在 **聊天模式 + Seedance 2.0 Fast + 15 秒** 时可用。切换模式或模型后若不符合条件，应移除音频再提交。首次排障时先用纯文字，可以避免把素材上传问题和 15 秒生成问题混在一起。

## 四、方案二：工作模式生成 15 秒

### 第 1 步：确认工作模式条件

在聊天模式的基础准备之外，确认：

1. 选定 Dola 账号有可用浏览器会话，可以进入工作 / 协作入口。
2. 账号绑定的代理已启用并可用。
3. 账号的工作额度当前可用；普通日额度与工作额度分开处理。
4. 如果账号来自 Cookie 导入，服务器已准备对应 CloakBrowser 环境，而非仅有纯 HTTP 运行路径。

当前代码按 Dola 独立工作额度及恢复时间处理调度。界面里普通日额度显示充足，不代表工作额度一定可用；以账号提示、工作额度恢复时间与上游回执为准。

### 第 2 步：切换为工作模式

1. 打开“创作工作台”，选择准备好的 Dola 账号。
2. 点击 **“工作模式”** 卡片，打开生成配置。
3. 或在账号行点击“生成”，再在窗口中选择 **“工作模式”**。

切换后必须重新核对模型、时长和条数，不要只看卡片是否高亮。

### 第 3 步：填写第一条工作任务

| 配置项 | 首次填写 |
| --- | --- |
| 模式 | **工作模式** |
| 视频模型 | **Seedance 2.0 Fast** |
| 视频时长 | **15 秒** |
| 画面比例 | 16:9 |
| 视频条数 | **1 条视频** |
| 提示词 | 可使用上一节湖面提示词，便于比较 |
| 参考素材 | 首次留空；基础生成通过后可再加图片 |

当前工作模式不支持参考音频。Dola 2.5 也不能在当前界面选择工作模式；遇到模式被禁用时，先确认模型是否为 Seedance 2.0 Fast。

### 第 4 步：提交并核验

1. 点击一次“开始生成”，记录任务 ID。
2. 后台进入工作空间，选择相应模型与时长并执行生成。
3. 在“任务列表”观察进度，完成后打开“视频作品”。
4. 播放作品，核对实际时长和画面；具体核验方法见下一节。

工作流程可能包含额外的入口导航和参数设置，也可能由工作助手整理提示词，因此准备耗时与提示词表现可能与聊天模式不同。不要承诺固定几分钟完成。

### “2 条视频”和“2.0 的 15 秒”开关是什么

工作模式的相应 **Dola Fast + 15 秒** 组合可以选择“两条视频”，含义是两条各 15 秒的结果，不是单条 30 秒。首次操作保持一条即可。

历史配置中还有“2.0 的 15 秒”开关，主要影响没有显式指定模式的 `auto` 兼容请求。当前表单明确发送 `chat` 或 `work`：聊天 15 秒进入专用流程，工作模式按显式工作请求判断。**不需要通过反复切换旧开关来切换这两种主模式。** 窗口并发则是独立的资源配置。

## 五、怎样确认真的生成了 15 秒

按下面顺序检查同一个任务：

1. **请求参数**：模式正确，时长为 15 秒；首次条数为 1。
2. **任务状态**：最终为“完成” / `completed`，并有作品地址。
3. **视频作品**：点击预览，实际播放，确认画面和时间都在推进。
4. **文件时长**：需要精确确认时，下载文件并查看媒体信息。
5. **视频尺寸**：本指南以 16:9 横屏操作，720P 样例为 1280×720；其它画面比例应核对对应实际尺寸。

有 FFmpeg 的环境可执行：

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=width,height:format=duration -of json output.mp4
```

已记录的聊天与工作样例均为 **1280×720、15.104 秒**，界面显示 15 秒。这种编码与封装造成的小幅差异属于不同计时口径；完整证据见 [真实运行验收记录](LIVE-ACCEPTANCE.md)。这些历史结果不代表所有账号现在都能成功。

收到任务 ID、出现“已提交”、模式卡片显示“15s”，都只是中间状态。最终以任务结果、可播放作品和文件时长确认。

## 六、豆包批量管理怎么开始

豆包批量管理是项目的另一条主线。操作顺序如下：

1. 进入“账号管理”，使用现有豆包账号添加或批量导入入口，按提示提供 Cookie 文本 / JSON 等资料。
2. 设置账号代理，完成登录验证，查看账号是否可用、闲置及对应额度。
3. 按账号选择生成模型；豆包模型以 `doubao-` 开头，不能套用 Dola 模型名。
4. 选择账号执行任务，随后统一查看任务状态与视频作品。

当前界面对豆包账号类型进行模式约束：工作类账号使用工作模式，个人类账号使用聊天模式。因此豆包账号切换模式被锁定，不等于 Dola 的双模式功能损坏。

批量登录并发、生成并发和浏览器窗口并发是不同设置。首次先用单账号、单任务跑通，再逐步增加数量，便于确认账号问题与服务器负载。

## 七、接入 API 时怎样指定两种模式

网页使用者可以跳过本节。接入自己的网站或脚本时，在“API 密钥”创建业务 Key，并确保该 Key 允许 15 秒。服务器还需要有能承接相应模型与模式的账号。

聊天模式请求体：

```json
{
  "model": "seedance-2.0-fast",
  "execution_mode": "chat",
  "prompt": "清晨湖面，远山与薄雾，固定机位，连续自然镜头，时长15秒。",
  "duration": 15,
  "ratio": "16:9",
  "video_count": 1,
  "reference_source": "unspecified"
}
```

工作模式请求体：

```json
{
  "model": "seedance-2.0-fast",
  "execution_mode": "work",
  "prompt": "清晨湖面，远山与薄雾，固定机位，连续自然镜头，时长15秒。",
  "duration": 15,
  "ratio": "16:9",
  "video_count": 1,
  "reference_source": "unspecified"
}
```

两份模板只改变 `execution_mode`，便于分别验证两种执行路径。将其中一份以 UTF-8 保存为 `request.json`，填写实际服务地址和业务 Key，再提交：

```bash
export DOLA_BASE_URL='https://studio.example.com'
export DOLA_API_KEY='REPLACE_WITH_YOUR_BUSINESS_KEY'

curl --fail-with-body --silent --show-error \
  --request POST "${DOLA_BASE_URL%/}/v1/videos/generations" \
  --header "Authorization: Bearer ${DOLA_API_KEY}" \
  --header "Content-Type: application/json; charset=utf-8" \
  --data-binary @request.json
```

保存返回的实际 `id`，然后查询原任务：

```bash
export DOLA_TASK_ID='REPLACE_WITH_RETURNED_TASK_ID'

curl --fail-with-body --silent --show-error \
  "${DOLA_BASE_URL%/}/v1/videos/${DOLA_TASK_ID}" \
  --header "Authorization: Bearer ${DOLA_API_KEY}"
```

等待 `completed` 后读取 `video_url` 或 `videos`。请求返回成功只是任务受理，不能用它代替最终视频验证。不要用管理登录会话替代业务 Bearer Key。更多字段见 [API 接入](../README.md#api)。

## 八、首次使用常见问题

| 现象 | 先检查什么 | 下一步 |
| --- | --- | --- |
| 没有 15 秒选项 | 是否打开当前版本生成窗口，是否选择 Dola + Seedance 2.0 Fast | 重新核对模型与模式；对照网页实际资源版本，加载当前前端后再操作 |
| 工作模式灰色或点不了 | 是否选了 Dola 2.5，或选中了模式受限的豆包账号 | 本指南改用 Dola Fast 账号与模型；豆包按实际账号类型使用 |
| 提示纯 API 号不能跑工作模式 | Cookie 运行路径与浏览器会话是否已准备 | 由部署者核对 CloakBrowser 环境及账号登录态；单改请求字段不能补齐环境 |
| 提示没有代理或代理不可用 | 账号是否绑定了启用代理，服务器是否能访问该代理 | 修复绑定与连通性，再验证账号；不要只看本机代理软件状态 |
| 一直检查页面状态 | 是否停在登录跳转、验证或异常页面 | 查看对应账号浏览器与阶段日志，先解决登录状态，不重复派发生成 |
| 日额度充足，工作模式仍不可用 | 工作额度和恢复时间 | 工作额度独立处理；按上游回执与账号提示判断 |
| 返回 710022002 或上游拒绝 | 原任务是否已提交、具体账号及出口错误 | 保存任务 ID 和原始错误，先核查原会话结果，不循环重发 |
| 生成了 10 秒或时长不符 | 实际请求是否为 15 秒，任务结果有无时长校验错误 | 核对请求与文件；若当前任务已失败但出现可播放结果，仍需确认是否满足目标时长 |
| 音频输入被禁用 | 是否是 Dola Fast + 聊天 + 15 秒 | 恢复这个组合，或移除音频；工作模式当前不支持音频 |
| 任务等待或准备较久 | 账号占用、窗口槽位、全局并发与代理 | 查看当前阶段和资源占用；不要同时重复提交同一账号 |

第一次验证成功后，再增加参考素材、视频条数、账号数量或并发。修改一个条件后观察一次完整结果，方便发现哪一步导致变化。

关闭生成窗口只关闭前端页面，后台任务继续执行。客户端超时也不代表上游停止；结果未知时先查原任务与原会话。
